## 📌 문제 정의

본 프로젝트는 건물별 전력사용량 시계열 데이터와 기상 데이터를 활용하여  
미래 전력 소비량을 예측하는 문제를 다룹니다.

데이터는 100개 건물의 시간 단위 전력사용량과  
기온, 습도 등 외부 요인으로 구성되어 있으며,  
각 건물의 전력 소비 패턴을 정확하게 예측하는 것이 목표입니다.

해당 문제는 다음과 같은 특징을 가집니다.

- 건물별 전력 소비 패턴의 강한 이질성  
- 시간(시/요일/계절)에 따른 주기성  
- 기상 변수에 대한 높은 의존성  
- 건물 단위 데이터의 제한된 규모  

즉, 본 문제는  
이질적인 시계열 데이터와 외부 요인이 결합된 예측 문제로,  
단일 모델로 접근하기에는 한계가 존재합니다.

## 📂 데이터 이해

데이터는 크게 세 가지로 구성됩니다.

- 전력사용량 시계열 데이터
- 기상 데이터 (기온, 습도, 풍속 등)
- 건물 메타데이터 (건물 유형, 면적 등)

EDA를 통해 다음과 같은 중요한 특징을 확인했습니다.

### 1. 건물별 패턴 차이

건물별 전력사용량은 동일한 시간대라도 완전히 다른 형태를 보였습니다.  
일부 건물은 일정한 주기성을 보였지만, 일부는 불규칙한 변동이 크게 나타났습니다.

→ 단일 모델로 모든 건물을 학습할 경우 평균화된 패턴만 학습되어 성능 저하 발생


### 2. 휴일 패턴의 다양성

일반적인 “주말 = 휴일”이라는 가정이 성립하지 않았습니다.

- 주말에 운영하는 건물 존재
- 특정 요일만 휴무인 건물 존재
- 정기 휴무가 없는 건물 존재

→ 휴일 여부를 단순히 외부 변수로 처리하는 것은 부적절


### 3. 이상치 존재

특정 구간에서 급격한 전력 소비 변화가 존재하며,  
이는 모델 학습에 영향을 줄 수 있는 요소로 판단되었습니다.

## 🧩 데이터 전처리

### 결측치 처리

태양광 용량, ESS 용량 등 일부 변수는 결측 비율이 매우 높았으며,  
해당 변수들은 정보 손실 대비 노이즈 영향이 크다고 판단하여 제거했습니다.

### 이상치 처리

건물별 시계열 데이터를 직접 시각화하여 이상치를 탐지했습니다.  
단순 통계 기반 제거가 아닌, 패턴 기반으로 판단하여 제거했습니다.


### 휴일 패턴 반영

건물별로 서로 다른 휴일 패턴을 반영하기 위해:

- 요일별 전력 소비 패턴 분석
- 반복되는 저소비 구간 탐지
- 이를 기반으로 휴일 관련 파생 변수 생성

→ 데이터의 실제 행동 패턴을 반영한 전처리 수행

## 🧠 Feature Engineering

Feature Engineering은 모델 성능에 가장 큰 영향을 준 핵심 단계입니다.

### 시간 기반 변수

- hour, weekday, month
- sin / cos 변환을 통한 주기성 반영

→ 주기성을 선형 모델에서도 학습 가능하도록 변환


### 기상 기반 변수

- 체감온도 (온도 + 습도)
- Cooling Degree Days (CDD)
- Cooling Degree Hours (CDH)

→ 냉방 수요를 반영하는 핵심 변수


### 통계 기반 변수

- 평균, 최대, 최소
- 온도 및 습도 변화량

→ 환경 변화에 따른 소비 패턴 반영


### 전력 패턴 변수

- 주간 추세 (slope)
- 시간/요일별 평균 소비량
- 변동성 (표준편차)

→ 시계열 구조를 직접적으로 반영

## 🤖 모델링

## 🔹 1. 건물별 모델 (Local)

- 모델: TabPFN
- 방식:
  - 건물별 독립 학습
  - K-Fold 기반 OOF 예측 생성
  - Linear Regression으로 보정 (Stacking)

### TabPFN 사용 이유

건물별 데이터는 약 2,000개 수준으로 매우 제한적입니다.  
일반적인 트리 기반 모델은 이 정도 데이터에서 과적합 또는 불안정한 예측을 보일 가능성이 큽니다.

TabPFN은 사전학습된 Transformer 기반 모델로,  
소규모 tabular 데이터 환경에서 강력한 성능을 보이는 것이 특징입니다.

### 스태킹 사용 이유

건물별 모델은 데이터 수가 적기 때문에  
모델의 예측값이 fold마다 흔들리는 문제가 발생했습니다.

이를 해결하기 위해:

- K-Fold 기반 OOF 예측 생성
- 해당 예측값을 입력으로 Linear Regression 학습

을 적용했습니다.

Linear Regression을 선택한 이유는 다음과 같습니다.

- 모델이 단순하여 과적합 위험이 낮음
- 예측값의 분산을 줄이고 smoothing 효과 제공

즉, 스태킹의 목적은 성능 향상이 아니라  
예측 안정성 확보입니다.


## 🔹 2. 건물 유형별 모델 (Group)

- 모델: TabPFN
- 방식: 동일 유형 데이터 통합 학습

### 스태킹 미사용 이유

건물 유형별 데이터는 개별 건물보다 데이터 수가 충분합니다.  
따라서 모델 자체의 예측 안정성이 확보되며,  
추가적인 보정 과정이 필요하지 않다고 판단했습니다.


## 🔹 3. 전체 모델 (Global)

- 모델: AutoGluon

AutoGluon은 다양한 모델을 자동으로 학습 및 앙상블하는 AutoML 프레임워크입니다.

### 선택 이유

- 전체 데이터를 활용하여 일반화된 패턴 학습 가능
- 내부적으로 앙상블이 적용되어 안정적인 성능 확보

## 🧠 프로젝트를 통해 느낀 점

이번 프로젝트를 통해 가장 크게 느낀 점은 모델보다 데이터에 대한 이해와 전처리 과정이 훨씬 중요하다는 점이었습니다. 초기에는 다양한 모델을 적용하고 성능을 개선하는 데 집중했지만, 일정 수준 이상에서는 성능 향상에 한계가 있음을 경험했습니다. 이후 데이터를 다시 분석하는 과정에서 문제의 핵심이 모델이 아니라 데이터에 있다는 것을 확인할 수 있었습니다.

특히 전처리 단계에서 단순히 결측치를 채우거나 통계적으로 이상치를 제거하는 방식이 아니라, 건물별 전력사용량 시계열을 직접 시각화하며 데이터를 하나씩 확인하는 방식으로 접근했습니다. 이를 통해 급격한 변동 구간이 실제 패턴인지 노이즈인지 구분하고, 반복적으로 나타나는 패턴은 유지하면서 비정상적인 값만 선별적으로 제거할 수 있었습니다. 또한 건물별로 상이한 휴일 패턴을 시각적으로 분석하여 이를 파생 변수로 반영하는 등 데이터의 실제 특성을 최대한 반영하고자 했습니다. 이러한 과정은 모델 성능 개선에 직접적인 영향을 주었으며, 데이터를 얼마나 정교하게 다루느냐가 결과를 좌우한다는 점을 체감할 수 있었습니다.

다만 전처리를 수작업 기반으로 수행하다 보니, 보다 체계적이고 정량화된 기준을 적용하지 못한 점은 아쉬움으로 남았습니다. 특히 이상치 처리를 좀 더 정교하게할 수 있었다면 추가적인 성능 향상도 가능했을 것으로 판단됩니다.

또한 모델링 측면에서는 단일 모델의 성능을 높이기보다는 데이터를 구조적으로 나누고 다시 결합하는 접근이 훨씬 효과적이라는 것을 확인할 수 있었습니다. 건물별, 유형별, 전체 모델을 각각 학습하고 이를 계층적으로 결합하는 방식은 서로 다른 수준의 정보를 동시에 활용할 수 있게 해주었고, 이를 통해 보다 안정적인 예측이 가능했습니다. 이 과정을 통해 모델링은 단순한 알고리즘 선택의 문제가 아니라, 문제를 어떻게 구조화하고 접근하느냐가 더 중요하다는 점을 깊이 이해할 수 있었습니다.

결과적으로 이번 프로젝트는 데이터 해석 능력과 전처리 설계 능력, 그리고 구조적 모델링 전략의 중요성을 체계적으로 경험할 수 있었던 과정이었습니다.
